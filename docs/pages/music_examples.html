Introduction

The ZX Spectrum 128K plays music on the AY-3-8912 chip; the Game Boy has its own sound chip with four channels. Pulse 1 and Pulse 2 make square-like waves with a choice of 4 duty cycles (Pulse 1 can also sweep its pitch up or down). The Wave channel plays a 32-sample, 4-bit waveform that you draw. The Noise channel makes noise from a shift register, for drums and effects. Volume fades come from a hardware envelope on the pulse and noise channels, so a note starts and fades with no more work for the CPU.

A tracker song is a list of patterns, each a grid of notes by rows. The Music Editor turns every row into the sound register writes that produce those notes, and the exported player just replays them, once per frame. The editor's preview uses the same writes, so what you hear is what the console gets. The programs on the other pages, starting with Tiles, share the helper routines explained there.

Exporting from the Editor

  1. In the Music Editor, click a cell and play notes on the keyboard (Z–M, and Q–U one octave up). Each channel has its own instrument and octave, used for the notes you enter next (notes already entered keep theirs; change a single note by clicking it). Instruments… edits duty cycles, envelopes, the pulse sweep, the drawn waveform and the noise type. On the noise channel the note sets the pitch of the noise.
  2. Set the speed: the number of video frames (1/60 s) per row. Build the order the patterns play in. The song loops.
  3. Click Export RGBDS (.asm) and name the file song. song_music.json is the two-pattern song used here: load it with Load project. (Export C writes a header with the same data and player for GBDK.)

The Exported Data: song.asm

The file starts with the speed and sizes, and a few bytes of RAM for the player:

[[lines music/song.asm 1-18]]

The song itself is the order list, a table of the patterns, and then each pattern as a stream. A pattern starts with its number of rows; each row starts with the number of register writes it needs, followed by that many pairs of register and value (the register is the low byte of its address, $FF00+n). The first row of the first pattern starts a note on all four channels: Pulse 1 (NR10–NR14), Pulse 2 (NR21–NR24), the wave channel, which first has its waveform copied into wave RAM, and the noise channel (NR42–NR44) for a kick drum:

[[part music/song.asm | song_order:: | ; row 1]]

Rows with nothing new to do have a count of 0 and cost one byte. The register writes are exactly the ones the hardware needs: NR12 is the envelope ($F0 is volume 15 with no fade, $F2 fades), NR13 and NR14 are the low and high bits of the pitch with bit 7 of NR14 meaning “start the note”. The wave channel's waveform can only be changed while the channel's DAC is off, which is why NR30 is written 0 before wave RAM and $80 after.

The Player

The same file contains the player. song_init switches the sound chip on and sets the master volume (NR52, NR50, NR51), and rewinds the song. song_update is called once per frame: it counts frames, and when a row is due it replays that row's register writes through ldh [c], a, which stores A at $FF00 + C. When it reaches the end of a pattern it moves to the next in the order list, and at the end of the list back to the start. song_stop turns all four channels off.

[[part music/song.asm | song_init:: | SECTION "song_music_data"]]

The Program: music_demo.asm

The program is short because the player does the work. The one rule is that song_update must be called exactly once per frame, which is what WaitFrame guarantees. (Real games usually call it from the VBlank interrupt handler so the music stays in time however long the game takes to run.) A stops the music with song_stop and B restarts it with song_init.

[[file music/music_demo.asm]]

Assembling and Running

[[text]] make music/music_demo.gb # assemble, link and fix the header make run-music/music_demo # ...and open it in mGBA [[/text]]

The screen stays blank; there is only sound. The test script runs this ROM on an emulated Game Boy with sound switched on, listens to the first row and checks that the notes the editor put there (C5 on Pulse 1, C4 on Pulse 2 and C3 on the wave channel) are the loudest frequencies in the output.

Things to try: change the speed in the editor to 4 and export again; draw a new waveform and give the bass a different sound; give Pulse 1 an instrument with a downward sweep for a laser effect.

The Same Thing in C with GBDK

Export C writes song.h with the data and a player with the same three functions. Include it in one .c file and call the player once per frame. (As with the C on the other pages, this follows the GBDK documentation but is not run by the test script.)

[[text]] #include #include "song.h" void main(void) { song_init(); while (1) { wait_vbl_done(); /* one frame */ song_update(); } } [[/text]]
