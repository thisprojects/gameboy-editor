Introduction

The ZX Spectrum scene editor produces a screen of pixels with colour attributes. The Game Boy has no screen of pixels: the picture you see is a grid of tile numbers, the background map, drawn with the tiles in VRAM. The map is 32×32 tiles (256×256 pixels) but the screen shows a window of only 20×18 tiles (160×144 pixels). Two registers, rSCX and rSCY, say where that window is, and it wraps round the edges of the map. That is all a scrolling background is.

The first example, Tiles, shows how tiles get into VRAM; this one adds the map. Its helper routines are explained there.

Exporting from the Editor

  1. In the Map Editor, import your tileset (a file saved from the Tile Editor, or a .2bpp), pick tiles in the palette and paint the map. meadow_map.json is the map used here: load it with Load project, tileset included.
  2. Choose the Export area: the full map (32×32), just the screen (20×18 at the SCX/SCY you set) or the used area (the box around every tile that is not tile 0).
  3. Click Export RGBDS (.asm) and name the file meadow. (Export map (.tilemap) is just the map bytes, Export tiles (.2bpp) just the tiles.)

The Exported Data: meadow.asm

The file starts with the sizes and the tile data, as in the Tiles example. Only the tiles up to the highest number the map uses are included.

[[part map/meadow.asm | DEF MEADOW_TILE_COUNT | SECTION]]

Then comes the map: one byte per cell, one db line per row, MEADOW_MAP_WIDTH bytes wide. This is the start of it:

[[part map/meadow.asm | meadow_map:: | ; row 4]]

A byte is a tile number, so a map can use at most 256 different tiles. Because the exported area can be smaller than the 32×32 hardware map, the width and height are exported as constants, and the program has to copy the map one row at a time.

The Program: map_viewer.asm

Copying the map

The tiles go to $8000, the map to $9800. The program first fills the whole hardware map with tile 0 (video memory is not empty when a program starts: the boot ROM leaves its logo in it), so any cell the export does not cover shows tile 0. The hardware map is always 32 tiles wide, so the copy loop then moves the destination on by VRAM_MAP_W - MEADOW_MAP_WIDTH after each row. With the full 32×32 export that is zero; with the 20×18 screen export it skips the 12 cells of each hardware row that the export does not cover.

[[part map/map_viewer.asm | Start: | ld a, %11100100]]

Scrolling

The loop keeps the scroll position in two variables. At the start of every VBlank it copies them to rSCX and rSCY, then reads the keys and changes the variables. (The scroll registers take effect straight away, so changing them in the middle of a frame would tear the picture.) Because the window wraps round the 256×256 map, the edges of the meadow are all trees: scrolling past one edge shows the other, so the map seems endless.

[[part map/map_viewer.asm | .loop: | INCLUDE "util.inc"]]

Assembling and Running

[[text]] make map/map_viewer.gb # assemble, link and fix the header make run-map/map_viewer # ...and open it in mGBA [[/text]]

Use the direction keys to scroll. Things to try: export just the screen area from the editor (set SCX and SCY to choose which part) and run the program again without changing it — the row-by-row copy handles the smaller map; change rBGP to %00011011 for a negative picture; or add a second layer of interest by turning on sprites as in the Sprites example.
