Introduction

The Game Boy has a sound chip (the APU) with four channels. Pulse 1 and Pulse 2 make square-like waves with a choice of 4 duty cycles (Pulse 1 can also sweep its pitch up or down). The Wave channel plays a 32-sample, 4-bit waveform that you draw. The Noise channel makes noise from a shift register, for drums and effects. Volume fades come from a hardware envelope on the pulse and noise channels, so a note starts and fades with no more work for the CPU.

A tracker song is a list of patterns, each a grid of notes by rows. The Music Editor turns every row into the sound register writes that produce those notes, and the exported player just replays them, once per frame. The editor's preview uses the same writes, so what you hear is what the console gets. The programs on the other pages, starting with Tiles, share the helper routines explained there.

Exporting from the Editor

  1. In the Music Editor, click a cell and play notes on the keyboard (Z–M, and Q–U one octave up). Each channel has its own instrument and octave, used for the notes you enter next (notes already entered keep theirs; change a single note by clicking it). Instruments… edits duty cycles, envelopes, the pulse sweep, the drawn waveform and the noise type. On the noise channel the note sets the pitch of the noise.
  2. Set the speed: the number of video frames (1/60 s) per row. Build the order the patterns play in. The song loops.
  3. Click Export RGBDS (.asm) and name the file song. song_music.json is the two-pattern song used here: load it with Load project. (Export C writes a header with the same data and player for GBDK.)

The Exported Data: song.asm

The file starts with the speed and sizes, and a few bytes of RAM for the player:

; song - 2 pattern(s), order length 2, 6 frame(s) per row
;
; Usage: call song_init once, then call song_update once per frame (for example from your VBlank
; handler). Call song_stop to silence the sound chip. The song loops. Needs RGBDS 0.5.0 or later.
;
; The data is a stream of sound register writes: per row a write count, then (register, value) pairs
; where the register is the low byte of $FF00+n. The player simply replays them.

DEF SONG_TICKS_PER_ROW EQU 6
DEF SONG_ORDER_LENGTH EQU 2
DEF SONG_PATTERN_COUNT EQU 2

SECTION "song_music_ram", WRAM0
song_tick: db
song_rows_left: db
song_order_pos: db
song_row_ptr: dw

The song itself is the order list, a table of the patterns, and then each pattern as a stream. A pattern starts with its number of rows; each row starts with the number of register writes it needs, followed by that many pairs of register and value (the register is the low byte of its address, $FF00+n). The first row of the first pattern starts a note on all four channels: Pulse 1 (NR10–NR14), Pulse 2 (NR21–NR24), the wave channel, which first has its waveform copied into wave RAM, and the noise channel (NR42–NR44) for a kick drum:

song_order::
    db 0, 1

song_patterns::
    dw song_pattern0
    dw song_pattern1

song_pattern0:
    db 16 ; rows
    db 33 ; row 0
    db $10, $08 ; NR10
    db $11, $80 ; NR11
    db $12, $F0 ; NR12
    db $13, $06 ; NR13
    db $14, $87 ; NR14
    db $16, $80 ; NR21
    db $17, $F2 ; NR22
    db $18, $0B ; NR23
    db $19, $86 ; NR24
    db $1A, $00 ; NR30
    db $30, $01 ; wave RAM 0
    db $31, $23 ; wave RAM 1
    db $32, $45 ; wave RAM 2
    db $33, $67 ; wave RAM 3
    db $34, $89 ; wave RAM 4
    db $35, $AB ; wave RAM 5
    db $36, $CD ; wave RAM 6
    db $37, $EF ; wave RAM 7
    db $38, $FE ; wave RAM 8
    db $39, $DC ; wave RAM 9
    db $3A, $BA ; wave RAM 10
    db $3B, $98 ; wave RAM 11
    db $3C, $76 ; wave RAM 12
    db $3D, $54 ; wave RAM 13
    db $3E, $32 ; wave RAM 14
    db $3F, $10 ; wave RAM 15
    db $1A, $80 ; NR30
    db $1C, $20 ; NR32
    db $1D, $0B ; NR33
    db $1E, $86 ; NR34
    db $21, $F3 ; NR42
    db $22, $7C ; NR43
    db $23, $80 ; NR44

Rows with nothing new to do have a count of 0 and cost one byte. The register writes are exactly the ones the hardware needs: NR12 is the envelope ($F0 is volume 15 with no fade, $F2 fades), NR13 and NR14 are the low and high bits of the pitch with bit 7 of NR14 meaning “start the note”. The wave channel's waveform can only be changed while the channel's DAC is off, which is why NR30 is written 0 before wave RAM and $80 after.

The Player

The same file contains the player. song_init switches the sound chip on and sets the master volume (NR52, NR50, NR51), and rewinds the song. song_update is called once per frame: it counts frames, and when a row is due it replays that row's register writes through ldh [c], a, which stores A at $FF00 + C. When it reaches the end of a pattern it moves to the next in the order list, and at the end of the list back to the start. song_stop turns all four channels off.

song_init::
    ld a, $80
    ldh [$FF26], a ; NR52: sound on
    ld a, $77
    ldh [$FF24], a ; NR50: master volume
    ld a, $FF
    ldh [$FF25], a ; NR51: all channels to both outputs
    xor a
    ld [song_tick], a
    ld [song_rows_left], a
    ld [song_order_pos], a
    ret

song_stop::
    xor a
    ldh [$FF12], a ; NR12
    ldh [$FF17], a ; NR22
    ldh [$FF1A], a ; NR30
    ldh [$FF21], a ; NR42
    ret

song_update::
    ld a, [song_tick]
    or a
    jr nz, .wait
    call song_play_row
    ld a, SONG_TICKS_PER_ROW
.wait:
    dec a
    ld [song_tick], a
    ret

song_play_row:
    ld a, [song_rows_left]
    or a
    call z, song_next_pattern
    ld a, [song_row_ptr]
    ld l, a
    ld a, [song_row_ptr + 1]
    ld h, a
    ld a, [hl+]
    or a
    jr z, .done
    ld b, a
.write:
    ld a, [hl+]
    ld c, a
    ld a, [hl+]
    ldh [c], a
    dec b
    jr nz, .write
.done:
    ld a, l
    ld [song_row_ptr], a
    ld a, h
    ld [song_row_ptr + 1], a
    ld hl, song_rows_left
    dec [hl]
    ret

song_next_pattern:
    ld a, [song_order_pos]
    ld e, a
    ld d, 0
    ld hl, song_order
    add hl, de
    ld a, [hl]
    add a, a
    ld e, a
    ld d, 0
    ld hl, song_patterns
    add hl, de
    ld a, [hl+]
    ld h, [hl]
    ld l, a
    ld a, [hl+]
    ld [song_rows_left], a
    ld a, l
    ld [song_row_ptr], a
    ld a, h
    ld [song_row_ptr + 1], a
    ld a, [song_order_pos]
    inc a
    cp SONG_ORDER_LENGTH
    jr c, .store
    xor a
.store:
    ld [song_order_pos], a
    ret

The Program: music_demo.asm

The program is short because the player does the work. The one rule is that song_update must be called exactly once per frame, which is what WaitFrame guarantees. (Real games usually call it from the VBlank interrupt handler so the music stays in time however long the game takes to run.) A stops the music with song_stop and B restarts it with song_init.

; music_demo.asm - play the song exported from the Music Editor
;
; Export "song" from the Music Editor (Export RGBDS) and put song.asm next to this file.
; It provides the player: song_init (once), song_update (once per frame) and song_stop.
; Press A to stop the music and B to start it again.

INCLUDE "hardware.inc"
INCLUDE "song.asm"

SECTION "Header", ROM0[$100]
    nop
    jp Start
    ds $150 - @, 0

SECTION "MusicVars", WRAM0
wPlaying: DS 1

SECTION "Main", ROM0[$150]
Start:
    call LcdOff              ; (nothing to draw: the screen stays blank)
    ld a, %11100100
    ldh [rBGP], a
    ld a, LCDCF_ON | LCDCF_BG8000 | LCDCF_BGON
    ldh [rLCDC], a

    call song_init           ; power the sound chip up and rewind the song
    ld a, 1
    ld [wPlaying], a

.loop:
    call WaitFrame           ; the player expects exactly one call per frame
    call ReadJoypad
    ld a, [wJoypad]
    bit PADB_A, a
    jr z, .notA
    ld a, [wPlaying]
    or a
    jr z, .notA
    call song_stop           ; silence all four channels
    xor a
    ld [wPlaying], a
.notA:
    ld a, [wJoypad]
    bit PADB_B, a
    jr z, .update
    ld a, [wPlaying]
    or a
    jr nz, .update
    call song_init           ; start again from the beginning
    ld a, 1
    ld [wPlaying], a
.update:
    ld a, [wPlaying]
    or a
    jr z, .loop
    call song_update
    jr .loop

    INCLUDE "util.inc"

Assembling and Running

make music/music_demo.gb       # assemble, link and fix the header
make run-music/music_demo      # ...and open it in mGBA

The screen stays blank; there is only sound. The test script runs this ROM on an emulated Game Boy with sound switched on, listens to the first row and checks that the notes the editor put there (C5 on Pulse 1, C4 on Pulse 2 and C3 on the wave channel) are the loudest frequencies in the output.

Things to try: change the speed in the editor to 4 and export again; draw a new waveform and give the bass a different sound; give Pulse 1 an instrument with a downward sweep for a laser effect.

The Same Thing in C with GBDK

Export C writes song.h with the data and a player with the same three functions. Include it in one .c file and call the player once per frame. (As with the C on the other pages, this follows the GBDK documentation but is not run by the test script.)

#include <gb/gb.h>
#include "song.h"

void main(void) {
    song_init();
    while (1) {
        wait_vbl_done();    /* one frame */
        song_update();
    }
}
