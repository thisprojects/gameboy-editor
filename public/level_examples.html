Introduction

A level is usually bigger than one screen and built from a few repeated blocks. Storing every tile would waste ROM, so the Game Boy editors work with metatiles: blocks of 2×2 or 4×4 tiles (16×16 or 32×32 pixels). The level is then a grid with one byte per metatile. A 32×32-tile level stored as a tile map takes 1024 bytes; as a 16×16 grid of 2×2 metatiles it takes 256 bytes plus a 28-byte table of the metatiles. A metatile can also carry a collision flag, so the game knows which blocks are solid without looking at pixels.

This example draws a level, lets you walk a small sprite around it that is stopped by solid blocks, and scrolls a camera to follow. It builds on Tiles, Map (the background map and scrolling) and Sprites; the helper routines are explained on the first page.

Exporting from the Editors

  1. In the Metatile Editor, import a tileset, choose the metatile size (the example uses 2×2) and build the metatiles. Tick Solid on the ones that should block the player. Save the project to use the metatiles in the Level Editor.
  2. In the Level Editor, import the metatile file and paint the level. cave_level.json holds the level used here, library included: load it with Load project.
  3. Click Export RGBDS (.asm) and name the file cave. (Export tile map (.tilemap) writes the level with every metatile already expanded to tile numbers, ready to copy to the background map.)

The tiles in the export are the ones the metatiles use, up to the highest tile number. The cave has a metatile of flowers for a reason: the program also uses the flower tile as the player sprite, and a tile that no metatile uses would not be in the export.

The Exported Data: cave.asm

Besides the tiles (as in the Tiles example) there are three tables. First the sizes:

; cave - 16x16 metatile level (32x32 tiles)

DEF CAVE_TILE_COUNT EQU 7
DEF CAVE_METATILE_COUNT EQU 7
DEF CAVE_METATILE_SIZE EQU 2
DEF CAVE_WIDTH EQU 16
DEF CAVE_HEIGHT EQU 16

The metatile table: four tile numbers per metatile (CAVE_METATILE_SIZE squared), row by row, followed by the collision table: one byte per metatile, 1 for solid.

; 4 tile indices per metatile, row-major
cave_metatiles::
    db $00, $00, $00, $00 ; metatile 0
    db $02, $02, $01, $01 ; metatile 1
    db $01, $01, $01, $01 ; metatile 2
    db $03, $03, $03, $03 ; metatile 3
    db $05, $05, $05, $05 ; metatile 4
    db $04, $04, $04, $04 ; metatile 5
    db $06, $06, $06, $06 ; metatile 6

; 1 = solid, one byte per metatile
cave_collision::
    db $00, $01, $01, $00, $00, $01, $00

; metatile index per cell, row-major

And the level map, one metatile number per cell (CAVE_WIDTH by CAVE_HEIGHT). The first rows:

; metatile index per cell, row-major
cave_map::
    db $05, $05, $05, $05, $05, $05, $05, $05, $05, $05, $05, $05, $05, $05, $05, $05 ; row 0
    db $05, $00, $00, $00, $00, $00, $00, $00, $00, $00, $00, $00, $00, $00, $00, $05 ; row 1
    db $05, $00, $00, $00, $00, $00, $00, $00, $00, $00, $00, $00, $00, $00, $00, $05 ; row 2

The Program: level_demo.asm

Setting up and the main loop

The example is written for 2×2 metatiles in a level 16 across and 16 down. That is 32×32 tiles, exactly the size of the hardware background map, so the whole level is drawn into it once and scrolling is just changing rSCX and rSCY. The ASSERT lines make the assembler stop if you export something else. (A larger level needs the map to be refilled with the part that is about to scroll into view; the principle is the same.)

Start:
    call LcdOff

    ld hl, cave_tiles
    ld de, VRAM_TILES
    ld bc, cave_tiles_end - cave_tiles
    call CopyBytes

    call DrawLevel

    ld hl, OAM_RAM
    ld bc, OAM_SIZE
    xor a
    call FillBytes           ; no sprites except the player

    ld a, START_X
    ld [wPlayerX], a
    ld a, START_Y
    ld [wPlayerY], a
    call UpdateCamera

    ld a, %11100100
    ldh [rBGP], a
    ldh [rOBP0], a
    ld a, LCDCF_ON | LCDCF_BG8000 | LCDCF_BGON | LCDCF_OBJON
    ldh [rLCDC], a

.loop:
    call WaitFrame
    call ShowScreen          ; scroll registers and the player sprite, during VBlank
    call ReadJoypad
    call MovePlayer
    call UpdateCamera
    jr .loop

Drawing the level

Each cell of the level map is a metatile number. The program looks up its four tiles in cave_metatiles (number × 4) and writes them as a 2×2 block of the background map, two tiles in one row and two in the row below, 32 cells further on.

; Expand the level map into the background map: every metatile becomes 2x2 tiles.
DrawLevel:
    xor a
    ld [wRow], a
.row:
    xor a
    ld [wCol], a
.col:
    ld a, [wRow]             ; metatile number = cave_map[row * 16 + col]
    swap a
    ld b, a
    ld a, [wCol]
    add a, b
    ld e, a
    ld d, 0
    ld hl, cave_map
    add hl, de
    ld a, [hl]
    ld l, a                  ; HL = cave_metatiles + number * 4: its four tile numbers
    ld h, 0
    add hl, hl
    add hl, hl
    ld de, cave_metatiles
    add hl, de
    push hl

    ld a, [wRow]             ; destination = VRAM_MAP + row * 64 + col * 2
    ld l, a
    ld h, 0
    add hl, hl
    add hl, hl
    add hl, hl
    add hl, hl
    add hl, hl
    add hl, hl
    ld a, [wCol]
    add a, a
    ld e, a
    ld d, 0
    add hl, de
    ld de, VRAM_MAP
    add hl, de
    ld d, h
    ld e, l
    pop hl                   ; HL = source tiles, DE = destination

    ld a, [hl+]              ; top row of the metatile
    ld [de], a
    inc de
    ld a, [hl+]
    ld [de], a
    ld a, e                  ; down one row of the background map (32 tiles) ...
    add a, VRAM_MAP_W - 1    ; ... we already moved one tile to the right
    ld e, a
    jr nc, .sameHigh
    inc d
.sameHigh:
    ld a, [hl+]              ; bottom row of the metatile
    ld [de], a
    inc de
    ld a, [hl+]
    ld [de], a

    ld a, [wCol]
    inc a
    ld [wCol], a
    cp CAVE_WIDTH
    jr c, .col
    ld a, [wRow]
    inc a
    ld [wRow], a
    cp CAVE_HEIGHT
    jr c, .row
    ret

Collision

Collision works on pixel positions. IsSolidAt divides a position by 16 (the size of a metatile in pixels) to find the cell, looks up the metatile there in cave_map, and reads its flag in cave_collision. Because the level is 16 cells wide, the cell number is just the high nibble of Y followed by the high nibble of X. Blocked asks about the four corners of the 8×8 player.

; B = x, C = y: pixel position in the level. Returns A = 1 if that spot is inside a solid metatile.
; Only A and HL are changed.
IsSolidAt:
    push de
    ld a, c
    and $F0                  ; (y / 16) * 16 = the start of that row of the level map
    ld l, a
    ld a, b
    swap a
    and $0F                  ; x / 16 = the column
    add a, l
    ld e, a
    ld d, 0
    ld hl, cave_map
    add hl, de
    ld a, [hl]               ; the metatile there
    ld e, a
    ld hl, cave_collision
    add hl, de
    ld a, [hl]               ; 1 = solid
    pop de
    ret

; B = x, C = y: top-left of the 8x8 player. Returns Z (zero flag set) if no corner is inside a solid metatile.
; BC is kept.
Blocked:
    push bc
    call IsSolidAt           ; top-left corner
    ld d, a
    ld a, b
    add a, 7
    ld b, a
    call IsSolidAt           ; top-right
    or d
    ld d, a
    ld a, c
    add a, 7
    ld c, a
    call IsSolidAt           ; bottom-right
    or d
    ld d, a
    pop bc
    push bc
    ld a, c
    add a, 7
    ld c, a
    call IsSolidAt           ; bottom-left
    or d
    pop bc
    ret

Moving the player

For each direction pressed, the program works out where the player would be one pixel further on and only moves there if that spot is not Blocked. Horizontal and vertical moves are tried separately, so the player slides along walls instead of sticking to them.

; Try to move one pixel in each pressed direction; the move is only made if the new spot is free
MovePlayer:
    ld a, [wJoypad]
    bit PADB_RIGHT, a
    jr z, .notRight
    ld a, [wPlayerX]
    inc a
    ld b, a
    ld a, [wPlayerY]
    ld c, a
    call Blocked
    jr nz, .notRight
    ld a, b
    ld [wPlayerX], a
.notRight:
    ld a, [wJoypad]
    bit PADB_LEFT, a
    jr z, .notLeft
    ld a, [wPlayerX]
    dec a
    ld b, a
    ld a, [wPlayerY]
    ld c, a
    call Blocked
    jr nz, .notLeft
    ld a, b
    ld [wPlayerX], a
.notLeft:
    ld a, [wJoypad]
    bit PADB_DOWN, a
    jr z, .notDown
    ld a, [wPlayerX]
    ld b, a
    ld a, [wPlayerY]
    inc a
    ld c, a
    call Blocked
    jr nz, .notDown
    ld a, c
    ld [wPlayerY], a
.notDown:
    ld a, [wJoypad]
    bit PADB_UP, a
    ret z
    ld a, [wPlayerX]
    ld b, a
    ld a, [wPlayerY]
    dec a
    ld c, a
    call Blocked
    ret nz
    ld a, c
    ld [wPlayerY], a
    ret

The camera

The camera is the player's position minus half a screen, kept inside the 256×256 map so that it never shows the wrap-around. In VBlank the scroll registers are set and the player's sprite is placed at its position minus the camera.

; Centre the camera on the player, but never scroll past the edges of the 32x32-tile map
UpdateCamera:
    ld a, [wPlayerX]
    sub 76                   ; (160 - 8) / 2
    jr nc, .xPositive
    xor a
.xPositive:
    cp MAX_SCROLL_X + 1
    jr c, .xInRange
    ld a, MAX_SCROLL_X
.xInRange:
    ld [wScrollX], a
    ld a, [wPlayerY]
    sub 68                   ; (144 - 8) / 2
    jr nc, .yPositive
    xor a
.yPositive:
    cp MAX_SCROLL_Y + 1
    jr c, .yInRange
    ld a, MAX_SCROLL_Y
.yInRange:
    ld [wScrollY], a
    ret

; Called at the start of VBlank: set the scroll registers and place the player sprite on the screen
ShowScreen:
    ld a, [wScrollX]
    ldh [rSCX], a
    ld b, a
    ld a, [wScrollY]
    ldh [rSCY], a
    ld c, a
    ld hl, OAM_RAM
    ld a, [wPlayerY]
    sub c
    add a, 16
    ld [hl+], a              ; screen Y + 16
    ld a, [wPlayerX]
    sub b
    add a, 8
    ld [hl+], a              ; screen X + 8
    ld a, PLAYER_TILE
    ld [hl+], a
    xor a
    ld [hl], a               ; attributes
    ret

Complete Source

; level_demo.asm - draw a level exported from the Level Editor, walk around it and scroll the camera
;
; Export "cave" from the Level Editor (Export RGBDS) and put cave.asm next to this file.
; It provides cave_tiles (the tiles used), cave_metatiles (4 tile numbers per 2x2 metatile),
; cave_collision (one byte per metatile: 1 = solid), cave_map (one metatile number per level cell),
; and the sizes CAVE_WIDTH, CAVE_HEIGHT and CAVE_METATILE_SIZE.
; Use the direction keys to move the flower; solid metatiles block it and the camera follows.

ASSERT CAVE_WIDTH == 16
ASSERT CAVE_HEIGHT == 16

DEF START_X      EQU 24
DEF START_Y      EQU 192
DEF MAX_SCROLL_X EQU 256 - 160
DEF MAX_SCROLL_Y EQU 256 - 144

SECTION "Header", ROM0[$100]
    nop
    jp Start
    ds $150 - @, 0

wCol:     DS 1
wPlayerX: DS 1               ; player position in the level, in pixels (0-255)
wPlayerY: DS 1

Assembling and Running

make level/level_demo.gb       # assemble, link and fix the header
make run-level/level_demo      # ...and open it in mGBA

Use the direction keys to walk the flower around. It is stopped by the rock, brick and ground, and walks through water, trees and the flowers (which are not solid). Things to try: mark the water as Solid in the Metatile Editor, re-export, and watch it become a lake; or add gravity by moving the player down every frame unless the spot below is Blocked.

The test script plays this program with random key presses for over a thousand frames and compares every position with an independent model of the same collision rules.
