Introduction

On the ZX Spectrum the ROM has a character set and routines to print text. The Game Boy has neither: there is no text mode and no ROM routine. A font is just 96 tiles (the characters from ASCII 32, the space, to 127) that you copy to VRAM, and printing a letter means writing its tile number into the background map. If the font is loaded at tile 0, the tile for a character is simply the character code minus 32.

This example builds on Tiles (tile data in VRAM) and Map (the background map).

Exporting from the Editor

  1. In the Font Editor, edit the glyphs. It starts with a built-in font; Load starter font restores it and Reset to starter restores one glyph. The preview shows your text the way a Game Boy screen lays it out, 20 characters to a row. gbfont_font.json is the font used here.
  2. Click Export RGBDS (.asm) and name the file gbfont. Export .2bpp gives the 1536 bytes of tile data; Export .1bpp gives 768 bytes (8 per glyph) for tools that expand 1-bit fonts themselves.

The Exported Data: gbfont.asm

All 96 glyphs are always exported, in ASCII order, each as an ordinary 16-byte tile with its code and character in a comment. The beginning of the file:

; gbfont - 96 glyph font (ASCII 32-127), Game Boy 2bpp
; Load to VRAM, then print character c as tile (c - GBFONT_FIRST_CHAR) + first font tile index.

DEF GBFONT_FIRST_CHAR EQU 32
DEF GBFONT_GLYPH_COUNT EQU 96

SECTION "gbfont_font", ROM0

gbfont_font::
    db $00, $00, $00, $00, $00, $00, $00, $00, $00, $00, $00, $00, $00, $00, $00, $00 ; $20 SPACE
    db $00, $00, $10, $10, $10, $10, $10, $10, $10, $10, $00, $00, $10, $10, $00, $00 ; $21 !
    db $00, $00, $24, $24, $24, $24, $00, $00, $00, $00, $00, $00, $00, $00, $00, $00 ; $22 "
    db $00, $00, $24, $24, $7E, $7E, $24, $24, $7E, $7E, $24, $24, $00, $00, $00, $00 ; $23 #

GBFONT_FIRST_CHAR is the code of the first glyph (32), and the end label gbfont_font_end lets the program work out the size. A font often only uses shades 0 and 3, but all four are available for shadows and outlines.

The Program: font_demo.asm

Loading the font

The font is copied to tile 0 onwards and the background map is cleared with tile 0, which is the space character, so the screen starts blank. The program then switches the LCD on and starts typing.

Start:
    call LcdOff

    ld hl, gbfont_font
    ld de, VRAM_TILES
    ld bc, gbfont_font_end - gbfont_font
    call CopyBytes           ; character 32 (a space) is now tile 0

    ld hl, VRAM_MAP
    ld bc, VRAM_MAP_W * VRAM_MAP_W
    xor a                    ; tile 0 = space, so this blanks the screen
    call FillBytes

    ld a, %11100100
    ldh [rBGP], a
    ld a, LCDCF_ON | LCDCF_BG8000 | LCDCF_BGON
    ldh [rLCDC], a

Typing the message

A pointer (HL) walks along a zero-terminated message and another (DE) along the background map. For each character the program subtracts GBFONT_FIRST_CHAR to get the tile number, waits a few frames, and stores it in the map. It waits by calling WaitFrame, which returns at the start of VBlank, the moment VRAM is safe to write while the LCD is on. Code 10 starts a new line: the low five bits of a map address are the column, so clearing them and adding 32 moves to the start of the next row.

    ld hl, Message
    ld de, VRAM_MAP + FIRST_ROW * VRAM_MAP_W + FIRST_COLUMN
.nextChar:
    ld a, [hl+]
    or a
    jr z, .done              ; 0 ends the message
    cp NEWLINE
    jr z, .newline
    sub GBFONT_FIRST_CHAR    ; character code -> tile number
    ld b, a
    call WaitFrame           ; one character every few frames, written at the start of VBlank
    call WaitFrame
    call WaitFrame
    ld a, b
    ld [de], a
    inc de
    jr .nextChar

.newline:                    ; go to the first column of the next row
    ld a, e
    and %11100000            ; the low 5 bits of the address are the column
    add a, VRAM_MAP_W
    ld e, a
    jr nc, .sameHigh
    inc d
.sameHigh:
    inc e                    ; (the low byte is a multiple of 32 here, so this cannot carry)
    jr .nextChar

.done:
    halt
    nop
    jr .done

Message:
    db "HELLO, GAME BOY!", NEWLINE
    db NEWLINE
    db "Typed with a font", NEWLINE
    db "from the Font Editor.", 0

Complete Source

; font_demo.asm - type a message with the font exported from the Font Editor
;
; Export "gbfont" from the Font Editor (Export RGBDS) and put gbfont.asm next to this file.
; It provides gbfont_font (96 tiles, one per character), gbfont_font_end and GBFONT_FIRST_CHAR (32).
; The tile for a character is simply (character - GBFONT_FIRST_CHAR), when the font is loaded at tile 0.

INCLUDE "hardware.inc"
INCLUDE "gbfont.asm"

DEF FIRST_COLUMN EQU 1
DEF FIRST_ROW    EQU 2
DEF NEWLINE      EQU 10

SECTION "Header", ROM0[$100]
    nop
    jp Start
    ds $150 - @, 0

SECTION "Main", ROM0[$150]
Start:
    call LcdOff

    ld hl, gbfont_font
    ld de, VRAM_TILES
    ld bc, gbfont_font_end - gbfont_font
    call CopyBytes           ; character 32 (a space) is now tile 0

    ld hl, VRAM_MAP
    ld bc, VRAM_MAP_W * VRAM_MAP_W
    xor a                    ; tile 0 = space, so this blanks the screen
    call FillBytes

    ld a, %11100100
    ldh [rBGP], a
    ld a, LCDCF_ON | LCDCF_BG8000 | LCDCF_BGON
    ldh [rLCDC], a

    ld hl, Message
    ld de, VRAM_MAP + FIRST_ROW * VRAM_MAP_W + FIRST_COLUMN
.nextChar:
    ld a, [hl+]
    or a
    jr z, .done              ; 0 ends the message
    cp NEWLINE
    jr z, .newline
    sub GBFONT_FIRST_CHAR    ; character code -> tile number
    ld b, a
    call WaitFrame           ; one character every few frames, written at the start of VBlank
    call WaitFrame
    call WaitFrame
    ld a, b
    ld [de], a
    inc de
    jr .nextChar

.newline:                    ; go to the first column of the next row
    ld a, e
    and %11100000            ; the low 5 bits of the address are the column
    add a, VRAM_MAP_W
    ld e, a
    jr nc, .sameHigh
    inc d
.sameHigh:
    inc e                    ; (the low byte is a multiple of 32 here, so this cannot carry)
    jr .nextChar

.done:
    halt
    nop
    jr .done

Message:
    db "HELLO, GAME BOY!", NEWLINE
    db NEWLINE
    db "Typed with a font", NEWLINE
    db "from the Font Editor.", 0

    INCLUDE "util.inc"

Assembling and Running

make font/font_demo.gb       # assemble, link and fix the header
make run-font/font_demo      # ...and open it in mGBA

Things to try: change the message (only the characters from space to ~ have glyphs); draw a different A in the editor and export again; load the font at a tile number other than 0 and add that number in the program; or print a number by turning a value into digits (character '0' is code 48).
